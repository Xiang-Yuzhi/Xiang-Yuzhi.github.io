XFund Promotion Agent 项目技术架构与实现深度解析 (V7.5)

2026-02-05T17:00:00.000+08:00 · Blog

本项目是一个高度集成的多智能体 (Multi-Agent) 协同系统，专门为基金公司的指数宣传和策略研究设计。通过将规则引擎与大语言模型 (LLM) 深度结合，在保证金融数据严谨性的同时，利用 AI 提升了政策解读和宣传策划的效率。

1. 核心架构设计

系统采用了 "前轻后重，多核分工" 的设计理念：

  • 底层框架 (Framework)：本项目未采用 AutoGen 或 LangGraph 等第三方重型框架，而是基于 Native Python + Flask + DashScope SDK 自研的一套轻量级 Agent 编排框架。
  • 架构范式 (Architectural Paradigm)：采取了 Router-Executor (路由-执行器) 范式，而非传统的 ReAct (Reason-Action) 范式。
  • 后端引擎 (AgentManager)：中央调度器，负责数据加载、状态演进、规则触发以及 4 个 Agent 的生命周期管理。
  • 通信枢纽 (app.py)：基于 Flask 搭建，采用 SSE (Server-Sent Events) 技术实现流式响应，显著提升交互体验。

2. 核心能力展示

  • 实时五维监控：系统模拟市场运行，实时监控规模里程碑、行情异动、周年庆、监管政策和产品动态。
  • RAG 增强问答：利用向量数据库索引历史信号，使用语义匹配技术实现高质量的背景知识找回。
  • 智能化意图识别：混合使用语义嵌入 (Embedding) 和关键词检测，精准将用户需求分发给对应的专家 Agent。
  • 自动化报告系统：支持一键解析长篇 PDF 政策，并按照固定模板生成排版精美的 .docx 研判报告。

3. 关键实现手段

A. 减少幻觉 (Accuracy & Reliability)

  1. 数据上下文注入 (Prompt Engineering with Data)：系统从不让 LLM 猜测行情。在调用 Agent 前，Python 逻辑会先从预处理好的 JSON 中提取当日的真实数据（如规模、成交额），并将其作为“强事实”注入 Prompt 模板。
  2. 规则导向的信号生成：对于规模排名、资金流入等敏感指标，使用硬编码的监测规则（check_rules），确保推送的消息 100% 准确。
  3. 专家路由逻辑：通过 get_intent 识别意图，确保“行情问题找小易，策划问题找小优”，避免模型在其不擅长的领域“一本正经地胡说八道”。

B. 提升速度 (Performance & Experience)

  1. 数据预处理 (preprocess.py)：定期将海量的 Excel 原始数据清洗、对齐并转换为结构化的 JSON，将后端查询耗时从秒级降低到毫秒级。
  2. LLM 响应缓存 (llm_cache.db)：内置 SQLite 缓存机制。相同的 query 在 24 小时内请求，会直接命中缓存，瞬间返回，极大节省了 API 成本和等待时间。
  3. 全流程流式输出 (Streaming)：通过 yield 逐步向前端推送生成的 Token，配合 UI 的打字机特效，让用户在首词返回时就能开始阅读，消除了长文本生成的枯燥等待。
  4. 异步预计算：启动时在后台线程预先计算全量历史信号并构建向量索引，确保历史回访和相似案例检索的极速响应。

C. 语义检索 (Semantic Search)

  • RAG 架构：集成了阿里云 DashScope 向量能力。当用户咨询“近期有什么宣传点”时，系统会自动搜索历史库中相似的成功信号作为参考案例供 Agent 借鉴。

4. Prompt Engineering 核心策略

系统通过精细化的 Prompt 工程实现了“高质量、低幻觉”的生成效果：

  • 动态事实注入 (Data Grounding)：系统绝不发送“空头问题”。每一个 Prompt 都会由后端补充 daily_context（当日行情摘要）和 rag_context（历史相似案例），将 LLM 的角色从“联想者”转变为“基于事实的分析师”。
  • 多智能体角色人格化 (Persona Setting)：
  • 单轮多维约束 (One-shot Constraints)：在 Prompt 中明确定义输出格式（如 Markdown 表格）、字数上限（如 150-200 字）及禁止项（如“无需重复用户问题”），确保输出结果直接可用。
  • 思维链视觉化 (Visualized CoT)：利用  标签模拟 Agent 的思考过程，在 UI 端提升用户对“深度研判”过程的信任感与耐受性。
  • 意图感知的系统提示词切换：根据路由识别的结果，动态切换不同的 system_prompt（例如“深度分析模式”对比“宣传建议模式”），实现一套模型、多种业务逻辑。

B. 架构要素核心描述 (用于绘图工具参考)

  • Top-Down 结构：表现为“用户指令 -> 混合路由 -> 事实增强 -> 专家生成”的单向极速链路。
  • 数据核心：以 processed_data.json 为行情事实底座，以 DashScope VectorStore 为智库检索核心。
  • Agent 范式：典型的 Router-Executor 模式，强调决策权上置和生成式回复。
  • 关键机制：Hybrid Routing（混合路由）、Signal Injection（信号注入）、Token Streaming（流式分发）。
